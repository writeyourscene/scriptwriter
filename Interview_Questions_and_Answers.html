1. System Architecture & Project Overview
Q1. What is the core purpose of the ScriptWriter application and what is its technology stack?

ScriptWriter is a premium web-based screenplay editing and project collaboration tool. It mimics professional screenwriting software (like Final Draft) by offering standard formatting shortcuts, pagination, auto-save mechanisms, AI writing helpers, character index management, and secure public script sharing.

Technology Stack:

  • Frontend: React (v19), Vite, Tailwind CSS (v4), Axios, framer-motion, and react-icons.
  • Backend: Java 17, Spring Boot (v3), Spring Data JPA, MapStruct, Lombok, OpenPDF, Apache POI.
  • Database: PostgreSQL.
Q2. Explain the system design and how client requests flow to the database.

The application follows a standard decoupled Client-Server architecture:

  1. The **Client (React)** initiates HTTP REST API requests via **Axios** to the server.
  2. The **Controller Layer** in Spring Boot intercepts request payloads, runs validations, and maps request DTOs (e.g. SaveScriptRequest) to system models.
  3. The **Service Layer** performs business logic (e.g., checking link expiration, parsing screenplay blocks, compiling stats).
  4. The **Repository Layer (Spring Data JPA)** translates operations into queries executed on the **PostgreSQL** database.
  5. The database responses flow back through mappers to output response DTOs (e.g., ScriptResponse) which are returned to the client in JSON format.
Q3. What is Vite and what are its key advantages compared to Webpack in a React project?

Vite is a modern frontend build tool that offers an extremely fast development environment. Its key advantages include:

  • Instant Server Start: It leverages native ES modules in the browser, serving code without pre-bundling. Webpack, conversely, bundles the entire application before starting the server.
  • Lightning-Fast Hot Module Replacement (HMR): Only updated modules are compiled and hot-swapped, regardless of the size of the application.
  • Highly Optimized Builds: Uses Rollup under the hood for production packaging, outputting highly optimized, split chunks.
Q4. Explain how framer-motion is used inside the editor page dashboard layout.

Framer Motion is a React animation library. In ScriptWriter, it is used to orchestrate smooth layout transitions for sliding panel drawers (such as the AI Assistant Panel and the Editor Settings Drawer):

  • It wraps the container in an <motion.div> component.
  • It uses the animate and exit attributes to transition CSS properties like x (transform-translate) and opacity when panels open or close.
  • This prevents jarring layouts and makes the panels feel lightweight and premium.
Q5. Why is PostgreSQL used as the primary database instead of a NoSQL database like MongoDB?

PostgreSQL was selected because screenplays, characters, users, and versions are highly relational entities that require strict data integrity:

  • ACID Compliance: Guarantees transaction safety when saving characters, blocks, and timeline statistics concurrently.
  • Rich Joins: Essential for mapping user permissions, project shares, and script version history.
  • JSONB Support: PostgreSQL offers a JSONB type which is utilized to store the array of dynamic screenplay block content in a single column while still allowing queries and updates, blending SQL structure with NoSQL flexibility.
2. Backend Development & Spring Boot Models
Q6. Explain how Hibernate manages database schema updates and the configuration setting used in this project.

In this project, Hibernate is configured in the application.properties using spring.jpa.hibernate.ddl-auto=update. This configuration instructs Hibernate to inspect the Entity classes (decorated with @Entity) on startup and compare them with the existing database schema. If there are missing tables or columns, Hibernate automatically executes SQL ALTER TABLE commands to synchronize the database schema without requiring manual migration scripts.

Q7. What is Lombok, and how do annotations like @Builder, @Getter, and @Setter work in Script.java?

Lombok is a Java library that plugs into the compiler to automatically generate repetitive boilerplate code like getters, setters, toString, equals, hashCode, and builders during build time.

  • @Getter / @Setter: Generates standard field getters and setters.
  • @Builder: Implements the Builder Pattern, allowing objects to be instantiated in a fluent, readable way (e.g., Script.builder().title("My Script").build()).
Q8. What is MapStruct, and how is it used in ScriptMapper.java to map between entities and DTOs?

MapStruct is an annotation-based code generator that simplifies mappings between Java bean types. During compile time, it generates code that handles mappings between JPA entity objects and REST payload DTOs. In ScriptMapper.java, it maps the Script entity to a ScriptResponse DTO, automatically converting fields like LocalDateTime and watermark objects.

Q9. How does ScriptWriter export screenplays to PDF and Word format?

Exporting is handled dynamically by backend utility classes:

  • PDF Export (ScreenplayPdfExporter): Uses **OpenPDF** (or iText) to construct PDF pages. It parses the JSON script content blocks, maps block types (Scene, Character, Action, Dialogue) to their industry-standard indentation rules, page-breaks blocks when they exceed page limits, and dynamically stamps watermarks onto the page canvases.
  • Word Export (ScreenplayDocxExporter): Uses **Apache POI** to build Microsoft Word files. It loops through the screenplay blocks, inserting paragraphs with specified formatting, fonts (Courier Prime), sizes, and margin indents mapped to each block type.
3. Frontend Development & React Editor
Q10. Explain how page breaks and page numbers are dynamically calculated in the React editor.

Because the editor uses a single continuous scroll text area structure, pages must be calculated dynamically on the client side:

  1. The editor loops through all screenplay blocks and calculates the cumulative vertical height.
  2. It uses an industry-standard height limit per page (e.g. 1050px for A4/Letter size at standard line height).
  3. Whenever the vertical height accumulator exceeds the limit, a virtual page break element is inserted into the rendering list.
  4. Each break records a page number index, rendering a .visual-page-break dividing line and a page number label in the margin.
Q11. Explain the difference between Page Zoom and Page Sizes ('a4', 'letter', 'script') in ScreenplayEditor.jsx.

Page Size dictates the target physical dimensions and print aspect ratio of the script pages (e.g. A4, US Letter, or Script size). This changes the height limits and page break margins inside the rendering logic.

Page Zoom is a purely visual presentation scale factor (managed by CSS transform: scale(zoom%) or font size multipliers) that allows writers to zoom in or out of the editor document without altering page formatting, layout boundaries, or line wraps.

Q12. What are custom hooks in React, and how is useAutoSave.js structured as a custom hook?

A **Custom Hook** is a Javascript function whose name starts with "use" and that can call other React hooks (like useState, useEffect, useRef). In ScriptWriter, useAutoSave.js abstracts the entire autosave process: it tracks the editor state, schedules timeout debounces, manages save states, and communicates updates to the script API. This keeps the main EditorPage.jsx component clean and maintainable.

Q13. Explain the configuration and event handling of PageNavigator.jsx.

PageNavigator.jsx renders a floating button indicating the current page count. When clicked, it opens a small input container:

  • Range Validation: The input restricts entries using HTML properties (min={1} max={totalPages}).
  • Keyboard Input: Listens for keydown events (e.key === 'Enter') to fire the jump function, allowing authors to hit Enter to jump instantly.
  • Callback Trigger: Fires onJump(pageIndex), which sets scroll coordinates inside the editor.
4. Database Schema Migrations & Concurrency
Q14. Explain the column type mismatch issue encountered when adding new watermark columns to the PostgreSQL database, and how we resolved it.

The Issue: Initially, new fields like watermarkEnabled were added to the Script entity as primitive booleans/doubles with nullable = false constraints. When Spring Boot booted up, Hibernate ran ALTER TABLE scripts ADD COLUMN watermark_enabled boolean not null. However, the database already contained existing rows (like project 28). Since existing rows had no data for this new column, PostgreSQL rejected the NOT NULL constraint insertion, causing a database exception which crashed all script loading APIs with a 500 Server Error.

The Solution: We changed the column types in Java to nullable wrapper classes (Boolean, Double, Integer) instead of primitive types, and added defensive getters to supply default values when columns are null in the database:

@Column(name = "watermark_enabled")
private Boolean watermarkEnabled = false;

public boolean isWatermarkEnabled() {
    return watermarkEnabled != null && watermarkEnabled;
}

This allowed Hibernate's ddl-auto=update schema migration to execute successfully because PostgreSQL could fill the existing rows with NULL values during the alteration.

Q15. Explain the auto-save collision problem and how our request-queuing pattern resolved it.

The Problem: When a user typed quickly, auto-save requests were triggered in quick succession. If a new request was sent before the previous database transaction completed, it resulted in overlapping concurrent database update calls. Hibernate threw concurrency exceptions or transaction deadlocks, resulting in save failures (red dot on UI).

The Solution: We implemented a sequential request-queuing lock inside useAutoSave.js using refs:

const isSavingRef = useRef(false);
const pendingSaveRef = useRef(false);

const save = async () => {
  if (isSavingRef.current) {
    pendingSaveRef.current = true; // Queue save
    return;
  }
  isSavingRef.current = true;
  // Send API request...
  // in finally block:
  isSavingRef.current = false;
  if (pendingSaveRef.current) {
    save(); // Trigger queued save
  }
}

This locks concurrent saves: if a save is active, any new changes are queued. Once the save completes, the queue immediately triggers a follow-up save with the latest data, ensuring no transactions overlap and no edits are lost.

Q16. Explain the role of @Builder.Default in Lombok entities and why it was required for our watermark fields.

Lombok's @Builder ignores initializations declared inline on entity fields (e.g. private String watermarkText = "CONFIDENTIAL";) during building operations unless @Builder.Default is present. If you instantiate an entity using the generated builder without manually setting this field, it builds with a value of `null` or `false` instead of the defaults, which causes database constraint violations or bad JSON rendering. Placing @Builder.Default ensures values are mapped appropriately.

5. Link Security & Copy Protection
Q17. How did we implement the 24-hour public link expiration feature? Explain both backend and frontend layers.

Backend Layer: We added a sharedAt column (LocalDateTime) to the Script entity. When a user enables sharing, sharedAt is stamped with the current time. In the sharing endpoint, we validate that the current time is within 24 hours of sharedAt:

if (script.getSharedAt() == null || 
    script.getSharedAt().plusHours(24).isBefore(LocalDateTime.now())) {
    throw new ResourceNotFoundException("This public link has expired");
}

Frontend Layer: We added dynamic countdown logic to PublicScriptPage.jsx that subtracts the current time from sharedAt + 24 hours. It updates every minute, displaying a countdown pill (e.g. Expires in 18h 4m) or showing an error if it expires in real-time.

Q18. How did we implement copy protection on the public view page?

We combined CSS-level locks and JavaScript-level event handlers to block copying:

  • CSS Rules (editor.css): We set user-select: none !important; and pointer-events: none !important; on all read-only screenplay input textareas. This completely prevents text selection, drag-highlighting, and cursor focus on the page.
  • JavaScript Blockers (PublicScriptPage.jsx): We registered window event listeners that cancel browser actions:
    1. Blocks the copy and cut events (preventing clipboard injection).
    2. Blocks the contextmenu event (preventing the right-click menu, hiding "Inspect Element").
    3. Intercepts keydown shortcuts to block Ctrl+C, Ctrl+A, Ctrl+S, Ctrl+P, Ctrl+U, and F12.
Q19. Why does the PDF exporter skip rendering header margins on Page 1? Explain the pagination logic.

Screenwriting standards dictate that Page 1 serves as the Title Page (displaying the screenplay name, draft version, date, and author contact). Standard headers and page numbers must **never** appear on this page. In ScreenplayPdfExporter.java, a conditional check if (pageNum == 1 && hasAuthorPage) is run to skip writing header text, margins, page numbers, or watermark templates on the first sheet.

6. Responsive Design & Layout Spacing
Q20. Explain why the Settings Cog icon was overflowing on mobile, and how you solved it.

The Issue: On mobile screens, the combined width of the Save Status block (84px text) and the 7 action toggles (Language, Search, Share, Import, Download, Sidebar, Settings cogs) exceeded 400px. Because most mobile viewports are 360px-390px, this caused horizontal layout overflow, pushing the rightmost Settings icon completely off the page.

The Solution: We optimized spaces in EditorToolbar.jsx:

  • Decreased save status text size to text-[9.5px] and width to w-[80px] to ensure it fits without wrapping.
  • Hidden the decorative vertical divider line on mobile (hidden sm:block).
  • Applied responsive padding/margins: container padding to px-2 sm:px-4, gaps to gap-0.5 sm:gap-1, and button paddings to p-1.5 sm:p-2.

This shaves off over 140px on mobile viewports, allowing the toolbar to fit comfortably on 320px+ mobile screens.

Q23. How did we fix layout responsiveness and dark/light mismatches on the Character Profile Modal?

Responsiveness: Changed columns like (Alias/Nickname, Age/Gender) from hardcoded grid-cols-2 to responsive grid wrappers: grid-cols-1 sm:grid-cols-2 gap-3. This stacks input fields vertically on mobile while splitting them cleanly into double columns on desktop.

Theme Mismatches: Replaced the hardcoded dark classes on textareas and dropdown selects with responsive tailwind classes: border-gray-200 dark:border-surface-700 bg-white dark:bg-surface-800 text-gray-700 dark:text-gray-300. This makes forms seamlessly turn white in light mode and dark gray in dark mode.

Q22. How does responsive width work inside the custom font family dropdown card?

The native HTML <select> element was replaced by a custom React dropdown card. The card is set with the Tailwind classes: absolute left-0 right-0 mt-1. Because the parent container has a CSS property of relative, the absolute dropdown card inherits the exact width of the parent flex block. It scales automatically based on viewport changes, staying perfectly aligned without overflowing on mobile screens.

7. Advanced Features & Editor Utilities
Q23. How does the Indian Language Transliteration feature function in the editor toolbar, and what is its value?

The transliteration feature allows writers to type phonetically in English (e.g. typing "namaste") and have it automatically transliterated into their selected Indian regional language (e.g., Hindi: "नमस्ते", Telugu, Tamil, Malayalam, Bengali, etc.).

It uses a custom transliteration helper utility (translitUtils.js) that captures user keystrokes in real-time, queries phonetic transliteration mappings, and replaces text buffer inputs dynamically inside the script editing block. This is of high business value for regional screenwriters and production houses who write dialogues in local scripts using standard English keyboards.

Q24. Explain how Search and Replace is implemented inside a block-based screenplay editor.

Because screenplays are divided into separate structural block elements (Scene Heading, Action, Character, Dialogue) rather than a single rich-text string, standard browser find utilities fail.

We implemented a custom FindReplaceModal that loops through the array of block objects, executes case-insensitive string matches (or regex patterns), highlights matched segments dynamically using background highlights, and replaces matches by updating the specific block index text and dispatching the state changes to React and auto-save hooks.

Q25. How is character statistics tracking (dialogues, timelines) compiled and managed?

We have a repository-level statistics compiler. When a screenplay is saved, the backend parses the dialogue blocks. It counts the number of times a Character name block is used (Dialogues count), compiles scenes in which they speak (Timeline list), and counts words spoken. In the database, characters are mapped in a characters table with relationships to scripts. A statistics endpoint returns a dynamic DTO containing the compiled metrics, which is displayed in the sidebar or in the profile edit modal.

Q26. How does the AI Coprocessor Panel (AiPanel.jsx) interact with the editor block state?

The AiPanel.jsx is integrated with the main editor screen. When opened, it can capture the active screenplay block or scene text. Users write a prompt (e.g. "Rephrase dialogue to sound more dramatic"). The prompt is sent to the backend, which invokes the AI Model API. The generated suggestions are streamed back, and users can click "Insert" to replace the block content or append it directly to the editor blocks list.

8. Security Configurations, Tools & Production Setup
Q27. Explain how authentication and route protection are handled between React and Spring Boot.

The backend uses **Spring Security** configured with a security filter chain. Users authenticate using login credentials, which return a secure session token (or JWT cookie) sent with subsequent Axios calls in the header.

The frontend protects private pages (like projects and editors) using a ProtectedRoute.jsx component. If the global auth context indicates that a visitor is unauthenticated, it cancels page rendering and redirects them to the log-in page.

Q28. How does Spring Security filter shared script requests? How is this configured?

In `SecurityConfig.java`, we define HTTP endpoint rules. To ensure public links are accessible to visitors without a log-in, we add a bypass rule:

http.authorizeHttpRequests(auth -> auth
    .requestMatchers("/api/v1/scripts/public/**").permitAll()
    .anyRequest().authenticated()
);

This allows the backend to serve public shared scripts on public routes while securing all project, block editing, character index, and account management API calls.

Q29. Explain how Cross-Origin Resource Sharing (CORS) is configured in CorsConfig.java.

Since the React client runs on a different port/domain (e.g. `localhost:5173`) than the Spring Boot server (`localhost:8080`), browser policies block cross-origin requests by default. In `CorsConfig.java`, we register a CORS filter:

CorsConfiguration config = new CorsConfiguration();
config.setAllowedOrigins(Arrays.asList("http://localhost:5173", "https://your-production-app.vercel.app"));
config.setAllowedMethods(Arrays.asList("GET", "POST", "PUT", "DELETE", "OPTIONS"));
config.setAllowedHeaders(Arrays.asList("Authorization", "Content-Type"));
config.setAllowCredentials(true);

This permits standard requests, header attachments, and cookie credentials from trusted domains.

Q30. How is the client and server set up for cloud hosting and production deployment?

Frontend (React Client): Deployed to platforms like Vercel. A vercel.json configuration handles routing rewrites so that single-page React router paths (like /projects/:id/editor) map correctly to index.html instead of throwing a 404.

Backend (Spring Boot Server): Packaged into an executable jar using Maven (./mvnw clean package) and hosted in a Docker container (using the custom Dockerfile) or cloud VMs (like AWS/Render/Heroku), communicating with a managed PostgreSQL database instance.
